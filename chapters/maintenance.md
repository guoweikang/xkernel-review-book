# 如何维护这本书

## 编辑位置

基础课程编辑 `chapters/`；原研究笔记编辑 `research/`；学习图谱同时维护
导航页 `chapters/map.md` 与完整概念记录 `research/KNOWLEDGE-MAP.md`。
不要编辑生成的 `.build/` 和 `dist/`。

## 正文与档案的边界

主结构固定为基础术语、流程地图、按环节展开。审查方向是横向维度，不与流程顺序混用。
每个环节说明输入输出、原理、第三方方法、X-Kernel 依据与实际效果边界；深入专题作为其子章节。
论文按所解决的问题关联到环节，不以论文发表顺序代替知识结构。
项目规范、已读源码、运行验证和实验效果分别标记；没有测量时不编写“收益已验证”。

课程正文保留概念、解释、推导、实例及相应来源。研究进度、对话经过、写作计划和来源审计记录放在附录。
不要用“将通过某例串联”等写作意图代替实际例子；例子应说明条件、分析和结论。
来源限制保留在相关论断旁，避免反复使用与具体内容无关的免责声明。
论文阅读日志不直接充当课程章节；其原始内容仍完整保存。

## 每次学习后

1. 补充概念、关系、例子与来源，不只堆术语。
2. 在研究档案中记录已讨论、待学习、待核实事项，不推断用户已经掌握。
3. 更新共同阅读笔记与来源台账；课程正文按知识主题组织，不写对话经过或个人学习进度。
4. 新研究想法进入候选区，查新与验证前不认定创新。
5. 运行构建和链接检查。

## 保留研究证据

原始资料本地留存，记录来源、时间及校验和；下载失败也记录。
Git 默认不跟踪原始全文，需单独备份；这不影响参考链接和证据清单入库。
历史记录保留原意，新增修正说明，不伪造原始讨论或实验。

## 发布

静态书不包含下载原文、Git 元数据或本地工具，但原笔记可能涉及私有项目语境和未公开
研究候选，公开前仍需审查。没有配置托管时，本地服务器地址只在对应网络范围有效。

# 从评审意见到自动化规则

一条意见指出的是具体问题；一条规则则要说明哪些情况应当检查、判断条件是什么、哪些例外成立。
将意见变成规则，还不等于将规则变成可执行检查。

## 两条不同的技术路线

| 工作 | 输入 | 输出 | 执行检查的主体 |
| --- | --- | --- | --- |
| Bugbot Learned Rules | 历史评审及反馈 | 影响未来审查的规则指令 | AI reviewer |
| Auto-SCAT | 历史行级评论与检查项知识库 | 已有静态检查项或类别的启用配置 | Checkstyle |

Bugbot 是产品实践；Auto-SCAT 是发表于 *Empirical Software Engineering* 的研究。
前者学习“以后审查时要注意什么”，后者选择“已有工具应该打开哪些检查”。
来源：[Bugbot 官方公告](https://cursor.com/blog/bugbot-learning)、[Auto-SCAT 论文](https://doi.org/10.1007/s10664-021-10076-4)。

## Bugbot：反馈成为审查指令

Bugbot 从评论反应、回复及人工审查中形成候选规则，随后根据反馈激活或停用。
官方文档还提供路径作用域与规则加载状态。这是一种持续维护项目审查知识的方式，
不等于把自然语言规则编译成 lint。[官方机制说明](https://cursor.com/blog/bugbot-learning)、[规则文档](https://cursor.com/docs/bugbot)。

其公告中的 resolution rate 使用 LLM 判断评论是否在合入前得到处理。这个指标反映处理行为，
不能直接解释为缺陷识别精确率；公告也没有提供规则学习模块的独立消融结果。

## Auto-SCAT：评论映射到已有检查项

Auto-SCAT 将历史评论与已有 Checkstyle 检查关联，通过文本表示、相似度和阈值推荐配置。
它依赖检查说明及人工映射的评论知识库，研究对象是 Java 项目。
方法的输出是已有检查的选择，而不是新 checker 的实现。[作者论文 §3](https://mdipenta.github.io/files/Auto_SCAT_EMSE.pdf)。

这解决了“团队反复要求的规范，是否可以由已有工具检查”的一部分问题。
但如果历史评论从未提到某种重要风险，不能据此推断该风险不需要检查；也不能直接把 Java 风格规则的效果迁移到 Rust 内核语义。

### 为什么不能只读最高分

论文表 4/5 报告，推荐启用具体检查时的平均精确率为 72.7%，推荐整类检查时为 96.3%。
这两个值的对象不同：类别命中比较粗，不能据此声称 96.3% 的 review 问题已经由工具覆盖。
详细的分母、阈值与未解决数值问题见 [Auto-SCAT 评价分析](../research/notes/2026-10-29-auto-scat-analysis.md)。

## 例子：安全注释的存在与内容

假设一条评论写道：“这段 unsafe 缺少安全说明，而且没有解释指针在操作期间为什么仍然有效。”
它至少包含两个检查要求：

| 要求 | 可能的检查方式 | 通过后仍不能推出什么 |
| --- | --- | --- |
| 是否有符合形式要求的注释 | 静态检查 | 注释内容正确 |
| 生命周期理由是否成立 | 结合调用方、所有权及释放路径分析 | 其他 unsafe 前置条件也成立 |

如果工具只检查第一项，就不能把整条意见标记为“已自动化”。
同样，工具在相同行报告了命名问题，也不代表它覆盖了生命周期问题。
覆盖关系应对应具体语义要求，而非只匹配文件、行号或关键词。

## 三种不同的评价对象

1. **映射正确性**：评论是否关联到正确的检查项？
2. **配置合理性**：启用的检查是否符合项目要求？
3. **执行覆盖**：在当前代码和配置上，检查是否真正运行并能发现目标问题？

前两项表现好，并不自动满足第三项。尤其在按 feature、平台选择编译代码的项目中，
检查项已启用，不代表目标代码进入了分析范围。

对于“跳过已自动化检查”的设计，还必须回答：覆盖是否完整、哪些例外被排除、工具失败时如何处理、
版本或配置变化后是否仍能沿用原结论。这些是条件免审需要解决的问题，不是上述两项工作的已证实能力。

## 与重复功能分析的关系

历史评论可以帮助识别反复出现的复用要求，例如“使用已有解析器”或“不要合并执行上下文不同的实现”。
然而，把这些意见保存成规则，不会自动解决功能等价、公共抽象质量或性能取舍。
规则学习负责积累约束；[公共抽象分析](abstraction.md)还需要检索实现并检验具体契约。

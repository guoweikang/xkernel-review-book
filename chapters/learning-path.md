# 阅读路线

## 先建立词汇，再看流程

1. [基础术语](basics/terms.md)：识别版本、变更、规则、上下文、证据与意见。
2. [职责与工具分工](basics/roles.md)：理解 AI、静态检查和测试分别能回答什么。
3. [流程全景](map.md)：理解输入、分析、核验、反馈和知识沉淀如何连接。
4. 按地图进入具体环节，阅读工程方法、研究证据和适用边界。

## 按问题进入章节

| 想解决的问题 | 对应环节 | 进一步阅读 |
| --- | --- | --- |
| 功能修改要哪些需求？兼容性何时查 Linux？文档是否要对照实现？ | [输入准备](flow/inputs.md) | 上下文与契约 |
| 大 diff 如何拆分？同一修改要不要多个方向一起审？ | [方向分配](flow/routing.md) | 配置、范围与遗漏 |
| 怎样判断重复功能、公共抽象和性能代价？ | [语义分析](flow/analysis.md) | 工程取舍、Librarian、Rust 重构 |
| 可疑问题是否成立？怎样表达不确定性？ | [核验与输出](flow/findings.md) | 证据强弱、测试边界 |
| AI 说得准不准？已采纳能否当正确标签？ | [反馈与评价](flow/evaluation.md) | Precision/Recall、Themis |
| 历史意见能否变成规则或 lint？什么时候可以减少重复审查？ | [知识沉淀](flow/learning.md) | Bugbot、Auto-SCAT、覆盖验证 |

各环节的深入内容是流程的一部分，不是一套与基础知识并行、没有先后关系的课程。

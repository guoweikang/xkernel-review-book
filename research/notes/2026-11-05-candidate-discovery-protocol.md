# 候选发现：怀疑清单的研究与评价协议

日期：2026-11-05。阶段 A 基础调研；任务是补齐发现环节，不替换既有六阶段或核验方案。
用户澄清“先发现、再确认优化”是核对已有分工，不要求再次调整总路线。
本轮不扫描真实重复案例、不运行检测器、不预定候选发现或补证机制一定成为论文核心。

## 1. 发现什么，不发现什么

目标是发现值得进一步比较的功能重叠，而不是第一次扫描就证明能够共享实现。
必须将三种不同输出分开：

- 检索线索：名称、文档或结构相近，尚未定位共同职责。
- 怀疑清单项：已指出可能共享的具体职责或实现片段，有可定位依据及已知差异。
- 优化建议：已进一步检查契约、使用条件及方案，属于后续确认/设计环节。

候选不以整个 crate 为唯一单位。首批研究单位建议是函数/方法、明确片段和紧密关联的小组；
mod/crate 是职责上下文与归属层，而不是看到目录相似就要求合并。
分散在多个小函数里的共同机制要保留为组合候选；其提取成本单列，不假定首版就有完整覆盖。
两个实现可以部分重叠；配对相关不具传递性，不能用相似图的连通分量直接生成可共同抽象的组。

## 2. 多路发现不是多次投票证明

下表是设计候选，不是已经实现的检索系统；方法依据沿用既有 P01、P11/P12、P21 与本地 facts 核查。

| 路线 | 提取和比较的线索 | 主要盲区/假阳性 | 研究中的作用 |
| --- | --- | --- | --- |
| token / 语法结构 | 相近实现片段、归一化后结构 | 写法不同的同功能可能漏掉；样板或短访问器可高度相似 | 成本与可解释性基线；必须明确 Rust 分词/片段划分的适配范围 |
| 文档 / 职责描述 | 问题、输入输出、状态和职责 | 文档复制、过时、缺失；同属内存管理不等于同功能 | 补充不同写法候选，保留声明原文，不只存模型摘要 |
| 类型 / 调用 / 数据使用 | 字段、不变量线索、特定底层操作及使用关系 | 通用依赖导致相似；动态调用和配置缺失；不同实现可能不共享任何底层对象 | 增加解释和上下文，不以图相似证明行为相同 |
| 现有能力检索 | 自定义实现与已有 crate/mod/API 的职责匹配 | 接口名称一致但契约不同；仓库外候选可能不适用于 no_std/许可证/配置 | 支持直接复用线索，首轮限定固定仓库/依赖范围，不无限扩张生态 |

先各自输出候选及来源，再统一身份、合并重复记录、保留各路证据和分数；分数不可直接跨模型比较。
共同依赖或相同描述可由同一根因产生，不能把三路命中当作三份独立证据。
归一化可以忽略局部命名，但不得丢弃用于核验的原始类型、常量、cfg 和操作顺序。
初始化、错误处理、宏展开等样板可降权，但不得无记录地全部删除，避免漏掉真正可共享的机制。

当前建议先做单路基线，再比较组合是否有新增有效覆盖；不以融合路线多作为成功标准。
是否需要向量数据库，应由实际检索规模与基线结果决定。

## 3. 一条可检查的怀疑清单项

| 字段 | 要求 |
| --- | --- |
| 范围 | 实现标识、源码位置、版本、所属模块及已知配置；无法对齐的项单列 |
| 重叠主张 | 明确可能共享的操作/职责；不只写“相似度高” |
| 原始依据 | 对应片段、文档段落或关系记录；模型摘要附出处并标为推断 |
| 差异 | 已发现的行为、输入、生命周期、上下文及配置差异；未检查项不能写不存在 |
| 来源 | 哪条召回路线发现、使用何种表示及版本、相关范围和限制 |
| 下一步 | 核验哪个问题能区分重复、部分重叠、合理独立或未知 |
| 优先级依据 | 重叠范围、潜在使用范围、核验成本等线索；不预报没有测量的性能收益 |

清单不默认附大规模重构补丁。排序决定先查哪项，不决定该项一定应该合并。
一个真实问题被多个片段和多路检索命中，应提供同一聚合入口并保留成员，避免重复占用人工预算。
聚合本身也应可撤销：若职责不同，不因为名称或依赖相近强行合并候选。

## 4. 如何评价“清单质量”

评价层次必须分开，避免以最终补丁成功率否定所有有价值的发现，也避免把相关性冒充优化价值。

| 指标层次 | 计量与分母 | 限制 |
| --- | --- | --- |
| 清单可核查性 | 实际审阅的前 K 个去重项中，位置/证据可复查且主张明确的数量 | 只是交付质量，不证明功能重叠 |
| 功能重叠相关性 | 同一前 K 项中，经独立核验确有全部或部分职责重叠的数量；未知单列 | 合理独立实现可能也有功能重叠，不计作已确认优化机会 |
| 可行动机会 | 同一候选范围内，确认存在值得继续的复用/局部抽象方向的数量及核验成本 | 尚非实际补丁验收，需后续行为和性能验证 |
| 已知机会覆盖 | 独立标注的已知机会中被检出的数量 | 仅限该标注集合；不能声称全仓真实召回率 |
| 增量贡献 | 组合路线比单路线新增的独立有效机会 | 同一问题多次出现不重复计数，相关函数对不当独立样本 |
| 工程成本 | 提取、建索引、扫描、人工审阅及重复检查成本，配套报告时间与资源 | 不只报告模型推理费用，也不混淆成本与内核运行性能 |

K、成本预算、标签定义在试点后冻结，不看测试结果再改。未知项保留在已审阅分母中并单列，
不能通过只计算能判定的少数项夸大 precision；需要时同时报告明确标注的条件指标及覆盖率。
初步指标不合成一个加权总分，保留性能与 clean code 的后续独立验收。

## 5. 避免发现实验的选择偏差

后续 B 的小批案例用于修订标签，不充当正式统计结论；C/D 才运行基线与机制实验。

- 受控构造集用于隔离改名、结构变化、部分重叠、样板等因素；保持行为需单独检查。
- 真实集来自多路线候选池、维护者线索及随机区域审阅，不能只从本工具输出选正例。
- 未重构代码不自动标负例；相似但合理独立属于需要识别的情形，未知不得强迫二选一。
- 覆盖 X-Kernel 之外的 Rust OS；先核对仓库身份、版本和派生关系，同源实现不能跨训练/测试冒充泛化。
- 历史重构只暴露改动前资料，后续补丁可供标注但不能泄露给检索；记录可能的训练污染。
- 保留“不同写法同功能”和“写法相近但契约不同”两类，分别发现召回和误报问题。
- 固定候选集评价核验与自然分布扫描评价发现分开进行；不将更强核验归因于更好召回，反之亦然。

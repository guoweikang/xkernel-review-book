# 伪文件候选反向核验

**范围。**2026-11-05，仅静态阅读指定归档，未下载、编译或执行测试。Starry 固定 `2e075accf4fb0aefdd1d252ebd9ccf29727d9923`，X-Kernel 固定 `7e3ac94431a0dbb376d2fc8d85098deeff1bba09`（各自 manifest／protocol）。下文 S 为 `research/evidence/runs/2026-11-05-starry-reading-scope-01/sources/kernel/src/pseudofs/`，X 为 `research/evidence/runs/2026-11-05-rust-pilot-seeds-01/sources/fs/kvfs/src/simple_file.rs`，T／D 分别为 `research/evidence/runs/2026-11-05-rust-pilot-context-01/sources/fs/kvfs/ut-tests/simple_file.rs` 与同 scope 的 `sources/fs/kvfs/docs/design.md`。本轮为独立 Agent 的反向阅读，**不是独立人工标注，不新增已验证正／负标签**。

**写入契约不能直接合并。**S `file.rs:131–144` 的 `write_at` 先 `read_all`；零偏移且输入不短于原内容时直接 `write_all(buf)`，否则复制旧内容、必要时补零、覆盖指定区间再整份提交。因此“每次必定复制旧内容”不成立，但“存在读改写路径”有源码支持。X `:82–127` 的 `CommandFile` 不以 offset 或旧内容拼接命令；`write_iter` 将非空请求完整复制后调用一次 callback，限制 4096 字节，空请求直接返回。4096 限制在 `write_iter`，不能泛化为任何直接 `write` 调用都有该限制；输入复制失败时不调用 callback，也不能据此声称 callback 副作用可事务回滚。T `:130–183` 声明了连续写、空写及 positioned write 的独立请求断言，D `:1121–1130` 说明设计意图；测试存在不代表本轮已运行通过。命令内容不使用 offset，也不意味着 VFS 文件位置不推进：T 明确断言首次写后位置为 5，定位写的显式 offset 从 123 到 133。这支持“相似包装下有不同写入契约”，尚不支持全系统可观察行为已穷尽比较。

**Read 的 `Ok(None)` 是局部契约差异，不是已证明系统漏洞。**S `file.rs:49–50` 在 callback 成功返回后直接 `unwrap`，故若 Read 返回 `Ok(None)`，局部代码会 panic；X `:77–79` 则返回 `InvalidData`，并原样传播 callback 错误。T `:15–21` 明确覆盖 missing／error／empty 三种预期。反向证据是 S `proc.rs:225–241` 的 `oom_score_adj`、`:275–300` 的 `comm`：Read 均返回 `Some`，Write 才返回 `None`，不能把 Write 的合法 `None` 当成 Read panic 可达证据。这两个使用点还展示了内容解析／设置策略，不能把包装器差异直接等同为真实 syscall 缺陷、权限绕过或可利用安全问题；本轮未审计完整调用链与 panic 策略。

**已有共享 read helper，不能将其包装层算作两份重复算法。**X `:353–355` 的 generated read 与 `:388–392` 的 snapshot read 已共同调用 `read_generated_bytes`（`:419–427`），共享 EOF、偏移切片和有界复制。差别是数据来源／生命周期：generated 调用 `read_all`，snapshot 取 per-open private data；T `:25–126` 与 D `:1283–1306` 给出快照稳定性及 seek 的预期，而非已取得运行效果。S `file.rs:120–128` 与该 helper 有局部相似的字节读取步骤，可保留为候选线索；不能因此声称两个文件类型可以整体互换、快照策略冗余，或再抽 helper 必有收益。源码中的复制／生成路径也不足以判定性能瓶颈或量化优化空间。

**可支持／仍不能支持。**目前支持：写入策略差异、Read 缺失内容处理差异、已实现的局部读取复用，以及测试／design 所陈述的约束。仍不能支持：安全合并方案、全系统等价、真实故障可达性、并发原子性、性能收益或代表性跨项目结论。Starry 固定原文入口为 [file.rs](https://github.com/Starry-OS/StarryOS/blob/2e075accf4fb0aefdd1d252ebd9ccf29727d9923/kernel/src/pseudofs/file.rs) 与 [proc.rs](https://github.com/Starry-OS/StarryOS/blob/2e075accf4fb0aefdd1d252ebd9ccf29727d9923/kernel/src/pseudofs/proc.rs)；本轮实际依据为上述本地归档，未在线访问。主线程与本 Agent 的一致阅读只增加交叉核查过程证据，不使候选变为独立人工确认的 ground truth。

# 重复功能与职责重构研究阶段报告

核查日期：2026-11-16。对象为本仓库已归档的论文笔记、实现、运行报告和检查结果；本次是证据综合，不是新增效果实验。xkernel 主试点沿用固定版本 `7e3ac94431a0dbb376d2fc8d85098deeff1bba09`，不代表最新主线。

## 一、整体判断

研究已经从资料调研进入**基线实际运行、Rust 适配和局部机制实验**。已有可重跑的候选生成、输入表示对照、职责映射诊断、契约检查和真实内核验证材料。它们尚未组成一个经独立评测证明有效的重构发现工具。

**文档帮助寻找重构点尚未闭环，但并非没有做过消融。** 已做词序、词表、文档与人工源码摘要输入对照；尚缺同一可比较范围、同一审查预算、独立任务标签下，代码、文档及二者融合的发现收益比较。

**确认环节已有局部实验闭环，不能替代发现收益闭环。** pagecache 的四组对照证明一个新增观测能区分已知变体；它没有证明能自动发现更多可重构对象。近期继续扩展计数接口的边际价值低于补齐发现评价，因此暂缓网络采集扩展。

## 二、目标与研究位置

目标是识别 Rust 系统软件中的重复功能、可共享局部机制和 crate 职责外散，确认共享条件，最终以行为、性能和维护成本评价精简方案。覆盖存量仓库及增量修改；AI review 只是应用出口。高质量论文和专利素材取决于实验贡献，不预先承诺结果。

“发现—确认—优化”是三个研究问题；以下六阶段是工作路线，两者不能混成一条完成百分比。

|工作阶段|已有成果|尚缺的阶段支撑|
|---|---|---|
|基础调研|技术谱系、代表论文阅读、查新线索、工具和评价边界分析|围绕最终候选机制补最近邻对照，不能宣称查新穷尽|
|真实案例试点|代码与文档候选审读、固件职责案例、契约种子案例|独立标签、覆盖合理独立与证据不足的稳定案例集|
|基线复现|SourcererCC 原工具及 Rust 前端；InMap 有输入替代的实际运行；部分 NLP 工具执行|不是全部原论文实验复现；仍缺任务对齐的统一基线评价|
|核心方法实验|表示、输入、选择器、契约与观测对照，含负结果|尚未证明一个聚焦机制具有独立、稳定的任务增益|
|真实场景验证|固定 xkernel 的局部补丁、内核测试和真实采集|全仓有效性、跨项目/配置、维护者确认及优化净收益|
|研究产出|阶段简报、历史论文草稿、来源和运行证据|支持最终贡献的评测与查新；尚不具备成熟创新结论|

各阶段已经有交叉探索，不代表前一阶段已全部验收。ArceOS、Starry 等仍是后续外部验证候选，不能列为已完成的研究对象。

## 三、按问题汇总方法、实验与证据

### 1. 输入材料能否支撑判断

固定快照盘点有 213 个 package manifest、145 份标准位置设计文档；数量表示存在性，不表示准确性或足够覆盖。已有 Rust 单元提取和调用拼写等事实输入，但不能称为完整、解析到实体的全仓调用图。见[输入专题](../../chapters/research-topics/inputs.md)。

文档规范不是被动接受现状：可以要求提供者补齐职责、输入输出、配置、前置条件、副作用、委托关系和边界，同时将整改成本单列。必须分开“规范要求谁负责”“当前代码做了什么”和“文档声称什么”。

已构造 3 个开发文档包、39 个变体；字段核查覆盖 24 个字段，得到 22 条证据关联、2 个配置未知、4 个需限定的陈述。固件材料中出现文档与当前查询路径不一致。后续拆为 15 个原子主张，以免规范归属被误当作现有能力。这些是开发材料，不是提供者已验收的正确文档数据集。

证据：[文档包](2026-11-12-governed-doc-packets.md)、[字段核查](2026-11-12-doc-field-evidence.md)、[原子主张](2026-11-12-governed-claims-v2.md)。

### 3. 职责归属能否由模型和文档确认

InMap 在 JabRef 的 842 个评价类上实际执行。因缺作者调用图，方法输入使用空反馈或 AST 定义方法名替代；不能写成原论文完整复现，更不能写成 Rust 职责检测效果。

|选择器|空方法反馈|AST 方法名反馈|
|---|---|---|
|原选择器|接受 823，拒绝 51|接受 839，拒绝 50|
|修正选择器|接受 832，拒绝 52|接受 839，拒绝 50|

2×2 与重复实验说明：方法输入的接受数增量随选择器变化（+16 与 +7），不能把全部增量归因于语义信息；接受数与现有布局一致也不代表架构更合理。这是方法名输入消融，**不是自然语言职责文档消融**。原始因素分析：`research/evidence/runs/2026-11-12-inmap-factorial-02/analysis.json`。

固件案例的两种职责模型×三个历史快照显示：严格模型始终有偏离；加一条允许边，偏离全部消失。关系来自调用拼写投影，解析到实体的边数为 0。因此“模型偏离减少”不能充当“设计改进”的标签。原始投影结果：`research/evidence/runs/2026-11-11-firmware-projection-01/report.json`。

### 4. 从相似走向可共享，需要哪些确认依据

已将候选覆盖、排序和确认分层；未知不等于负例。现有 156 对候选和开发家族尚无独立真值，新增抽样也不能因换了 pair 就自动成为独立测试集。见[分层评价](2026-11-12-layered-candidate-evaluation.md)。

NLI、依存分析和语义角色标注用于诊断“词语相似但角色、条件、规范含义不同”的困难，不是重构判定器。已运行 HANS 评价器、作者预测回放及模型推理控制；HanLP 有真实推理和 Rust 文本探针。局部规则组合会减少错误但同时漏掉原本正确的回答，说明必须共同报告错误与覆盖，而不是只报告拒绝率。执行与阅读层级见[证据状态](2026-11-11-research-evidence-status.md)及[确认专题](../../chapters/research-topics/confirmation.md)。

## 五、哪些结论成立，哪些仍待证明

已经有依据的工程结论：

- 词元基线在固定 Rust 输入上可运行、可核对；不同输入门槛严重影响候选比较。
- 文档词序和词表会改变排序，但简单词汇相似度不能可靠地区分角色反转和同义表达。
- 职责映射结果同时受模型假设、输入和选择器影响，不能只看一个接受数。
- 正确的契约观测可以揭示原测试没有区分的具体行为；运行记录完整性与语义覆盖是两回事。

尚未证明的核心命题：

- 规范化文档能在同等审查成本下增加**经确认**的重构或职责问题，而非仅增加候选。
- 候选确认机制能跨家族、跨项目稳定降低误判，且成本可接受。
- 建议的抽象在行为、性能和 clean code/维护成本上具有净收益。

值得保留的创新候选是“受约束且可追溯的职责文档＋多视角候选检索＋条件化确认”。这是待验证组合假设，不是已有创新结论。需要最近邻机制比较、独立标签、消融和外部验证后，再判断是否值得单独整理专利交底材料；目前不报告达到专利交接门槛。

## 七、下一批研究的优先级与完成判据

### 优先一：补齐文档辅助发现的任务评价

复用已完成的词序/词表/摘要实验，不重新包装成新成果。先冻结共同实体范围和长短函数分层，再比较代码、文档和融合；分别记录候选覆盖、固定 top-k 审查预算、运行成本。共同范围内的效果与范围外的增量发现分别报告。

文档因素至少区分原生、按规范补齐、缺字段和受控错误。完整文档可由提供者整改或由研究者构造，但二者身份、正确性证据及建设成本必须显式记录；不得用结果标签反向编写文档。角色、配置、委托和职责归属是重点字段，不把词面增益误写成重构收益。

独立判定至少区分已有委托、合理独立、可共享局部机制、职责外散、证据不足；与代码克隆标签分开。隔离开发/测试家族和历史已看过的文件；若独立标注条件不足，就只报告开发诊断，不能由同一模型同时产生方法和独立真值。

**完成判据：** 有冻结协议、同条件基线、全部条件原始结果、标签来源与分歧记录、逐例正负结果、消融和可重跑检查；无论是否有增益都形成结论。小样本不包装成总体统计结论，报告其范围和不确定性。

### 优先二：让确认服务候选，而不是发展成通用缺陷研究

冻结现有预算/事件工具为回归证据；暂缓继续扩展网络采集。由发现清单决定下一项契约或轨迹需求，仅实现能够改变候选结论的最小确认实验。已有测试能回答时直接复用；增加观测无新增收益也保留。

**完成判据：** 每项补证对应一个候选和一个未决条件，能解释为何维持、排除或仍未知；成本与新增信息一并记录。不能以检查器控制全部通过替代候选确认准确率。

### 后续：优化与外部验证

发现与确认评价稳定后，再选择有证据的候选做实际重构；比较行为、配置、性能及维护边界，保留合理不抽象的结论。外部 Rust 项目用于验证迁移，而不是为了扩大数量提前重复开发集。届时根据实际贡献更新论文及专利候选，不预设正结果。

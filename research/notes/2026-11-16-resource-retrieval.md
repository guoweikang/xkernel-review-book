# 研究资源检索与遗漏检查

## 问题与方法

现有材料不可能每轮全部重读。研究接续依赖的是可检查的查找路径，而不是 Agent 记忆：**问题定位 → 多词检索 → 原始证据核对 → 反例与后续修正 → 留下检索记录**。这套机制降低可观测的遗漏，不保证语义召回完整。

已核查的 [Scientific Agent Skills](2026-11-12-scientific-skills-assessment.md)提供检索、筛选、证据层级和竞争解释的流程参考；[持续执行机制](2026-11-12-research-execution-workflows.md)提供有界批次参考。本次采用它们的检查思想，不安装整套外部技能，不向外部服务上传材料，也没有新做系统性文献检索。

## 三层资源结构

|层|已有位置|检索用途|
|---|---|---|
|问题地图|十个研究专题、阶段报告、catalog|先明确问题及当前允许结论，避免从日志任意选下一步|
|来源和过程|SOURCES、manifest、论文笔记、协议、scripts|找到论文版本、原工具、输入、适配及实验设计|
|原始证据|evidence/runs、manifest登记的本地原件|核对实测分母、失败、对照、版本和适用边界|

不搬动原始目录，也不把这些内容再复制成另一份人工“总数据库”。catalog 是文档归属来源，manifest 是原件声明来源，运行目录是执行证据来源。研究结论仍由专题综合维护，检索命中不产生新的结论。

## 本地检索工具

`scripts/research_lookup.py` 使用 Python 标准库，读取当前文件，不依赖向量服务、模型或可能过期的缓存。支持中文与英文不区分大小写的字面子串检索，默认多词 OR，可切换 AND；结果包括文件位置、行号、片段、资源种类和截断数量。排序只是命中词数、路径，不是证据质量评分。

在仓库根目录运行：

```sh
python3 scripts/research_lookup.py --inventory
python3 scripts/research_lookup.py 文档 TF-IDF doc-tfidf --limit 30
python3 scripts/research_lookup.py InMap factorial --all --kind run
python3 scripts/research_lookup.py P01 --kind source
python3 scripts/research_lookup.py 角色 词表 --topic inputs
python3 scripts/research_lookup.py 2026-11-12-inmap-factorial-01
```

最后一种按运行 ID 检索可找引用它的分析、失败记录和相关文件；按具体脚本名、论文 ID、版本或完整路径同样可查。它是显式引用查找，不是自动证明因果关系的知识图谱。`--topic` 仅筛选已登记文档，不能用于判断某专题没有实验或来源；查原始材料时去掉该过滤。

每次输出都会列出资源清点与检索盲区：

- `text`：已读取的 UTF-8 文本；不是已理解或已人工核实。
- `metadata-only-format/size`：PDF/二进制或大于 2 MiB 的文件仅检索路径和来源声明；需要另外读取正文。
- `missing/no-local-path/unreadable-text/outside-root/symlink-not-read`：缺失、未声明本地路径或未读资源，不能当作有效全文命中。
- `omitted_hits`：超过显示上限的命中，不能把首屏当成全部检索结果。
- `navigation_gaps`：文档中没有字面提及的 run ID、脚本名，作为补链接候选；被提及也不保证关系正确或解释充分。

范围是 research（原件目录除外）、chapters、scripts、项目 skills 与 AGENTS；原件只纳入 manifest 登记项。未登记原件、外部仓库、`.tools`、`.build`、生成站点不全量扫描。manifest 中的下载状态和摘要只是声明，本命令不重新校验哈希、下载或解压资源。文件更新时重读避免缓存过期，但多文件读取不是原子快照。

## 每批研究的检索门槛

1. 写出本批问题，并阅读当前阶段报告、相关专题和 PROGRESS 顶部。历史记录中的下一步不得覆盖较新的运行结果。
2. 至少用问题词、方法/论文名、代码实体或运行 ID 三类入口查找；中英文术语分别查，不能假设自动同义词扩展。先广查，再收窄类型。
3. 找到支持证据后，还查相应失败批次、负结果、限制和后续修正。读取协议与原始结果的关键字段，不能只用片段或通过状态。
4. 查清当前范围缺了什么：文档归属用 catalog 检查，原件是否存在与正文盲区用 inventory，未关联 run/脚本由 navigation_gaps 提示。确定性检查与语义遗漏分开报告。
5. 在本批协议或笔记留下：问题、查询词/命令、命中数量与显示截断、实际打开的文件和位置、采用/排除理由、尚未读取部分。需要保留完整输出时写入 `.build/retrieval/`；其中有科学论断依据的关键记录再按批次归档，避免把整个检索输出循环索引成新证据。

只有完成这些检查，才能说“查过已有材料”。要说“未发现已有实验”，必须同时交代查询范围和盲区，不能写成绝对不存在。

## 验证与后续边界

2026-11-16 首次实际清点：4081 项，其中 2871 项可读文本、1198 项格式仅元数据、9 项超过大小上限、3 条来源没有本地路径。48 个 run ID、7 个脚本名未在扫描的说明文档中直接出现；这是字面关联缺口，不是已证实的48项研究遗漏。`文档 TF-IDF doc-tfidf --limit 30` 实际命中196项，返回30项并明示省略166项。计数会随文件变化，复核以重新运行输出为准。

本轮查询与清点输出保存在本地 `.build/retrieval/inventory.json`、`.build/retrieval/doc-query.json`，未作为科学实验或远端备份。首次清点暴露 manifest 中失败下载记录不含 path，已修正为保留 `no-local-path` 条目，并增加回归控制，而非静默丢弃这些来源。

`scripts/check_research_lookup.py` 使用隔离构造资源，检查中文/大小写/AND/类型和主题过滤、行号、缺失原件、超大文件、无效编码、外部链接以及修改和删除后立即生效。它验证实现行为，不测真实研究问题的召回率。

未来若字面检索反复漏掉已知相关材料，再从真实漏查案例建立固定查询集，比较词法检索、术语表和语义检索；同时评价相关证据召回、原始证据定位和读取成本。当前没有证据支持直接引入大规模向量库，亦不把“做了索引”视为研究创新。

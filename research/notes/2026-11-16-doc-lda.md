# 原生 Rust 文档主题基线：固定预算与种子敏感性

## 问题与方法身份

成熟主题模型是否会给出与直接词法文档检索不同、值得检查的候选？本轮采用 scikit-learn 1.7.2 的 LatentDirichletAllocation，在既有真实 Rust 文档上执行三个固定种子，不训练大模型、不下载权重。

方法动机来自[注释克隆论文精读](2026-11-09-comment-clone-method-reading.md)及其归档原文：Kuttal、Ghosh，*Source Code Comments: Overlooked in the Realm of Code Clone Detection*，arXiv:2006.14505v1。作者以文件注释主题分组；本实验使用函数绑定的直接文档、主题向量余弦和全局top20。作者工件与真值仍未取得，见[工件核查](2026-11-09-comment-clone-artifact-readiness.md)。因此这是**论文启发的 Rust 适配，不是作者实现或论文数值复现**。

LDA仍是词袋方法，不自动理解参数角色、否定范围、职责授权或实现是否已委托。为控制表示差异，沿用已有TF-IDF的分词和未移除停用词策略；这与论文预处理不同。10主题、20轮、种子17/29/43是事前固定的开发设置，不声称最佳或作者参数。

## 冻结输入与可复跑入口

- 协议：`research/protocols/doc-lda-v1.json`。
- 执行器：`scripts/run_doc_lda.py`；独立排名核对：`scripts/check_doc_lda.py`。
- 全部输出：`research/evidence/runs/2026-11-16-doc-lda-01/`。
- 原始输入：`2026-11-09-source-doc-inventory-02/bindings.json`，SHA-256 `d33a53d4cec538e3c5b52ca326486a2f15995dff3c46d518e7a964144bc30e89`。

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 .build/doc-retrieval-env/bin/python scripts/run_doc_lda.py --output research/evidence/runs/<new-run>
OPENBLAS_NUM_THREADS=1 .build/doc-retrieval-env/bin/python scripts/check_doc_lda.py research/evidence/runs/<new-run>
```

环境复用既有doc-retrieval-env，依赖锁定记录见原TF-IDF运行。freeze.json在训练前记录输入、协议、执行器、辅助函数和基线摘要。保存三个种子的完整文档主题分布、主题词权重、词表、前15主题词、候选排名和待审并集；未保存的训练内部状态不作为结果依据。

2180个绑定对象中780个分词后非零，1400个空输入保留在覆盖分母，但不参与LDA拟合和配对，避免空输入主题先验被误当候选。TF-IDF沿用原来全2180文档的IDF拟合。两者候选端点范围和审阅预算相同，拟合方法不同；不与旧SCC门槛直接比较准确率。

## 实测结果

| 比较 | top20交集 |
| --- | ---: |
| TF-IDF / LDA种子17 | 11 |
| TF-IDF / LDA种子29 | 15 |
| TF-IDF / LDA种子43 | 13 |
| LDA17 / LDA29 | 13 |
| LDA17 / LDA43 | 12 |
| LDA29 / LDA43 | 13 |

四份前20并集为38对，即18对未进入旧TF-IDF前20。交集不是准确率，也不代表18个新重构点。不同随机种子已改变候选集合，不能选择某一表现最好的种子报告。

事后增加并列诊断（不改原排序）：种子17有30对、43有29对的余弦四舍五入12位后等于1，均超过20预算；种子29有19对等于1，随后3对同为0.999999999999。因此部分top20成员由预先规定的对象ID字典序截断，而不是可解释的语义差异。不能把这些接近1的主题分布相似度叫作“100%重复概率”。本诊断保存在checks.json，不能冒充事前假设，也尚未分解短文档、主题压缩及数值精度各自的贡献。

概率有限性、正值、行和、余弦对角线通过；独立checker用另一算术路径重算三个种子的全部配对，前20排名完全吻合。重跑TF-IDF的20个对象对与历史结果一致。全部76候选端点对应的原始函数片段SHA已与units.zip核对。尚未宣称跨机器逐位复现。

当前主题词包含大量the/and等通用词；这是保存的诊断现象，不据此临时去停用词、调主题数并报告最优结果。若比较预处理，必须作为下一独立冻结批次保留本结果。

## 候选审阅与边界

历史TF-IDF的20对可追溯到[逐对源码审阅](2026-11-09-doc-tfidf-review.md)，不是独立人工真值。新增18对由主研究员逐个读取冻结units.zip函数片段；独立角色并行检查不视为独立人工标签。下表索引是review-queue.json的**零起始索引**，不是方法排名。不可变初始队列保留not_reviewed，本表作为追加静态审阅，不回写历史机器输出。

| 队列索引 | 函数对与源码观察 | 当前判断及未知 |
| --- | --- | --- |
| 0 | FileOperations::write/read都默认返回InvalidInput；切片分别共享/可变借用 | 默认返回片段相同，不等于读写职责相同；抽象收益未测 |
| 1 | Dentry::is_really_positive调用!is_really_negative；is_special_entry查flags | inode存在性与节点类型不同；尚无共同机制证据 |
| 8 | Once::call_once直接调用try_call_once，错误类型Infallible | 已有核心委托；不是两份独立初始化算法 |
| 9 | SuperBlock::lookup_inode转node::lookup_inode；另一端new_with_inode_attribute_operations构造inode并分派类型 | 查询与创建不同，仅主题相关；未发现共同局部实现 |
| 12 | Dentry::set_changed_at/set_link_count分别转发inode方法 | 已有下层委托，时间与链接计数状态不同 |
| 13 | empty_inode_operations克隆共享空表；另一端是generated_file_provides_the_linux_poll_fallback测试 | 生产接口与测试验证关系，不能据主题判重复实现 |
| 14 | Dentry::decrement_link_count/increment_link_count分别转发inode | 已委托；增减方向不同，不把方向差异直接判不可共享 |
| 16 | Dentry::is_special_entry/is_regular_entry调用flags不同谓词 | 同接入模式、不同类型判定；收益未知 |
| 17 | Dentry::is_special_entry/is_symlink_entry调用flags不同谓词 | 同上，未证实有必要新增抽象 |
| 19 | directory_operations/symlink_operations默认None，但返回不同dyn trait | 默认空行为相同、类型契约不同；收益未知 |
| 23 | Inode::set_accessed_at/set_modified_at转发attributes不同方法 | 已有属性层委托，时间字段角色不同 |
| 24 | Inode::set_accessed_at/set_changed_at转发attributes不同方法 | 同上，不合并时间语义 |
| 25 | Inode::symlink/mkdir都lock_location、require_directory_operations，再分派 | 可讨论共享锁/能力获取局部机制；参数target与mode不同，闭包/生命周期/成本待验证 |
| 28 | Inode::set_modified_at/set_changed_at转发attributes不同方法 | 已有属性层委托，不是两份完整存储实现 |
| 29 | Inode::set_link_count/decrement_link_count转发attributes | 设置与减少不同，底层原子/饱和约束尚未在本批核查 |
| 30 | Mount::filesystem_stat调用SuperBlock::stat，后者转ops.statfs | 已有跨层委托，不是独立统计实现 |
| 32 | __simple_unlink减少计数；simple_rename条件调用simple_unlink | 与34合看，已有间接复用；rename额外更新目录计数有不同上下文 |
| 34 | simple_unlink调用__simple_unlink；simple_rename调用simple_unlink | 已有直接调用链，剩余局部重复与收益未验证 |

本批未执行cfg或解析完整调用目标，没有语义编译/性能证据。对25保留局部机制候选，但它仍是已见语料的探索线索；不能以本表计算准确率。其余差异也不能机械地当作“没有重构空间”。

本轮不否定补写合格文档的研究路线：这是**原生输入成熟方法基线**，不是文档整改方法的最终检验。后续应在独立冻结的文档条件上比较，而不是以1400份缺失输入宣布方法无效。

## 决策与检索记录

采用Goodall审议建议：停止继续扩展自写职责规则自测，把资源转回成熟方法与真实候选。查询`research_lookup.py LDA comment-clone --limit 8`发现147项匹配，仅显示8项且终端输出截断，不称穷尽阅读。实际读了方法精读、工件就绪笔记、发现专题、TF-IDF执行器/协议、历史top20结论、输入样例及本次原始结果。PDF正文沿用已归档精读，本轮未重新全文阅读或重新搜索公开工件。

回收的Goodall反馈要求进一步收窄解释：top20交集与新增18对是“当前舍入、ID打破并列规则和预算共同产生的队列差异”，不代表主题模型更有区分力或稳定发现新机制；rounded=1也不证明原始向量完全相同。采纳此限制，保留原排名。其最后反馈针对解释边界，不能据此宣称已取得18对独立复核一致率；本表的逐对依据由主研究员负责。

完成边界：三种子、排名核验及18对追加源码审阅已完成；第二角色反馈单独记录，不替代真值。下一步不调LDA挑最优：冻结“相同主题但动作/对象不同、已有委托、局部机制共享”三种关系的文档干预评价设计，优先复用本批暴露的失败类型，并明确开发案例不能成为独立效果测试集。没有优化补丁、净收益、精确率/召回率或创新成熟结论。

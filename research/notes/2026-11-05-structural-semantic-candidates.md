# 结构与摘要语义候选：P11 / P21 定向对照

**1．范围。**2026-11-05，仅直接读取本地 `research/evidence/originals/P11-wrangler.pdf` 的 §4.1（印刷页6–9），以及 `research/evidence/originals/P21-librarian-v3-full.html` 的 §5。前者以 pdftotext、后者去除 HTML 标签生成临时文本；未运行检测器或重构工具、未联网扩检索。主源分别为 [Li 与 Thompson，Incremental Clone Detection and Elimination for Erlang Programs，§4.1](https://www.cs.kent.ac.uk/pubs/2011/3087/content.pdf) 和 [Librarian，arXiv:2506.11058v3，§5](https://arxiv.org/html/2506.11058v3#S5)。本轮不重核实验结果、§4.2 增量机制或 Librarian 附录 A。

**2．Wrangler：表达式序列的结构候选类。**输入 Erlang 源文件，绕过预处理以保留原文形态，不展开宏、包含或条件编译；AST 注释变量/函数名绑定与位置，并收集各函数中的表达式序列。结构泛化只替换允许的位置，保留模式、匹配及复合表达式等结构；表达式泛化后打印、哈希成整数序列，再以广义后缀树形成共享泛化表示的初始类。初始类不是最终可抽象类：逐成员进行 anti-unification，整体失败时还查子序列，一个初始类可产生零个、一个或多个满足用户参数的类，成员可重叠。输出还包括 anti-unifier（公共函数形式）、替换调用实例及排序，供用户判断是否消除。故其候选单位不是整个文件或必然完整函数，也不能把结构同形直接当作行为等价。（P11 §4.1）

**3．Librarian：文件摘要聚类作为重构任务分组。**输入任务中的文件集合；模型先总结每个文件，用 `text-embedding-ada-002` 对描述编码，再用凝聚聚类形成规模参数为 S 的文件组。作者明确区分“问题描述相似”与“实现代码相似”，因此不是直接复用 ReGAL 的题目描述分组。每组进入 sample-and-rerank，生成 K 个“新库＋迁移后文件”方案，按损失选择；简单方式合并各组库及改写文件，正文另提将已积累库传给后续组的扩展。文件组只是可能共享结构的搜索范围，不是经确认的克隆类；K 个候选是重构方案数，S 是文件组大小，不能混为克隆召回数量。（P21 §5，式2–5）

**4．Rust 对照命名与边界。**可称“借鉴 Wrangler 的结构泛化/anti-unification 候选路线”和“借鉴 Librarian 的文件摘要聚类路线”，不宜直接称为两工具的 Rust 复现。前者依赖 Erlang AST、绑定和表达式语义，迁移需明确 Rust 语法、宏/cfg 视图、所有权及副作用约束；后者换成 Rust 函数或模块、加入 facts 图关系、改变摘要模型或聚类过程，均是改编，应逐项声明。两者分别输出结构候选类与任务文件组，不能按组数直接比较优劣；应先由主线程统一候选单位及评估口径。本轮未验证 Rust 可运行性或召回效果，也未证明任一分组足以支持安全合并；这些是未知，不是断言原方法没有相关能力。

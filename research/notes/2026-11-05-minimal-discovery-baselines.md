## 1. 为什么不先做“大而全”的混合检测器

先回答三个可分离的问题：词法方法能找到哪些机会；语义表示是否补充不同写法的实现；
现有 facts 是否帮助定位或排序。若第一版同时混合摘要、关系图、人工文档和复杂评分，
即使发现有效候选，也无法判断是哪部分有用或哪里失败。
最小版本以只读候选清单为输出；不生成补丁、不自动阻塞 PR、不训练专用模型。

## 2. 首批比较对象与阶段命名

### 主比较：同一函数/方法集合

对象来自固定版本源码清单，记录源码范围、crate/mod 归属、cfg 线索和提取状态。
对具备解析来源的函数/方法构建统一集合；解析失败、宏生成、无法定位以及非当前配置对象分别登记。
全仓词法视图与选定配置的编译事实视图不能冒充同一覆盖范围。
可以在共同覆盖集合上比较方法，但必须同时报告被排除对象的数量与原因。

### 扩展比较：片段与分组

局部重复用同一片段划分协议单独评估；不要拿整函数方法与任意滑窗方法直接比较召回。
跨函数共同机制和三份以上实现保留为后续组级任务，不能把成对相似连成组即算完成。
本轮函数级方案是用于控制变量，不是放弃最终 mod/crate 和跨函数发现目标。

## 3. 先做哪些基线

下列 D0–D4 为本研究的实验臂编号，不是原作者系统名称；实现、模型及参数尚未选择。

| 实验臂 | 输入和机制 | 回答的问题 | 必须记录的限制 |
| --- | --- | --- | --- |
| D0 简单词法检索 | 名称、原始源码和可用文档的固定字段；简单文本检索 | 廉价方法是否已足够产生高价值线索 | 各字段单列/消融，避免文档贡献被隐藏；名称近似不是功能等价 |
| D1 token 重叠 | 相同代码单位的 token 多重集相似度，候选索引可借鉴 P01 | 相近实现和近似复制的基础覆盖 | Rust token/归一化规则、阈值和最低片段规模必须明确；不是 P01 原工具完整复现 |
| D2 源码向量检索 | 相同代码单位，固定模型和截断规则 | 不经过生成摘要时语义表示的增量 | 被截断对象单列，模型/版本固定；相似分数不可直接当概率 |
| D3 摘要向量检索 | 相同源码生成职责/实现摘要，再用与 D2 相同的向量模型检索 | 摘要是否改善发现，还是引入幻觉和额外成本 | 固定提示词、生成模型、缓存；保留原文依据，分离摘要成本和检索成本 |
| D4 关系证据增补 | 对相同候选池加入 facts 的类型/调用/使用信息做解释或重排 | facts 能否增加判断效率或改善前 K 项 | 先固定候选池测重排，再另测关系召回；不能把二者收益混算 |

实施顺序建议：D0/D1 先建立低成本参照，D2/D3 在明确模型与资源后加入，D4 等实际 facts 可用再加入。
不能因 D4 未就绪就冻结前面所有工作；但本轮仍只制定方案，正式运行遵循 B/C 阶段门槛。
若只能承担少量模型调用，先比较 D1 与 D2，不用人工编写高质量摘要替代 D3 后声称自动效果。

结构匹配保留为重要扩展参照：P11 是 Erlang 表达式序列、绑定信息和受限反统一，
简单 Rust AST 指纹并不等于 Wrangler。需明确实现的是结构近似还是绑定感知泛化，
在具备可复用解析/绑定接口及预算后纳入；未完成前不能宣称已超过结构方法。

## 4. 与 Librarian 的区别必须说清

P21 §5 的单位是文件，利用源码摘要分组后进行库重构；不是天然的函数对近邻检测器。
本方案 D3 只借鉴摘要表示，以统一函数单位检验其发现贡献，不能用其结果声称复现或战胜 Librarian。
若随后复现原方法，应另设文件级输入、分组和下游重构任务，保持作者任务语义。
原始文档作为新增信息另设条件；不能 D2 只看源码而 D3 额外读取完整设计文档后，把优势归于摘要。

## 5. 公平输出与融合

- 所有臂输出候选标识、成员位置、分数/排序、原始依据、限制和资源记录。
- 统一去除自身匹配、对称重复，并保留各路原始结果以审计聚合；同一机会多个片段不重复计收益。
- 固定展示前 K 个去重候选和人工审阅预算，不让输出更多的路线自动获得更高成功数。
- 不直接平均不同算法分数。第一轮以独立结果及并集新增机会分析为主，复杂融合留待基线之后。
- 单方法与组合均记录全部建索引/摘要成本；组合若使用更多总预算，需另设同预算比较。
- 自然扫描与人工给定候选的核验测试分开；未知不从分母悄悄删除。
- 在可用算力内做重复运行或记录无法重复的限制；不能将一次 LLM 排序的差异归为稳定改进。

## 6. 失败归因与停止条件

| 观察 | 先检查什么 | 不能直接得出的结论 |
| --- | --- | --- |
| 很多显然重复未出现 | 对象是否被提取、截断、过滤；阈值和配置是否覆盖 | 直接认定算法没有语义能力 |
| 摘要路线更好 | 是否更多上下文、人工修订、更多调用预算 | 摘要机制本身必然更优 |
| 关系路线候选少 | facts 的范围和缺失、候选池及间接关系 | 无调用边就是无重叠 |
| 前 K 项多为样板 | 去重、最小单位、公共调用降权与原始候选保留 | 一刀切删除错误处理或初始化代码 |
| 单方法已达到目标 | 检验成本和独立集稳定性 | 为凑贡献继续增加复杂模型 |
| Rust 适配失败 | 分词/AST/宏/构建接口，区分适配和算法错误 | 给原论文的原任务记失败或零召回 |

## 7. 进入执行前必须落实的条件

1. B 阶段评审通过的标签指南与首批案例；标注对象区分重叠、合理独立、可行动及未知。
2. 固定仓库版本、许可与同源关系；选定有效配置，说明源码集合与编译集合差异。
3. Rust 提取器/工具版本、支持范围与失败报告；目前尚未选定并验证。
4. 模型提供方、版本、数据外发政策、预算和可复现缓存；尚未决定，不默认可发送所有源码。
5. 前 K 项和成本预算、独立测试切分、最终测试前冻结的评价协议。
6. D4 所需实际 facts manifest/status/crate 制品；后续已取得双平台元数据与 klazy 样本，
   见 [执行准备核查](2026-11-05-execution-readiness.md)。全量验证与配置复现仍未完成，不能用示例伪造运行数据。

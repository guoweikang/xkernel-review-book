## 核心论断检查表

| 现有论断 | 判断 | 处理／仍需补齐 |
| --- | --- | --- |
| AI 像工程师理解上下文 | 项目期望 | 不写成现有系统已达到的能力 |
| 代码、评论、reviewer 三种对象 | 教学分类 | 保留，标明非统一行业分类 |
| 可机械化检查优先工具 | 工作流建议，B06 有相关实践 | 不称所有 lint 都能确定判错 |
| 设计并非只有审美 | B01/B02 支持方向 | 具体非法状态等例子属我们的说明 |
| 事实→影响→取舍 | 自编教学框架 | 不称标准流程，不暗示已评测有效 |
| 循环内分配必然变慢 | 原文已否定这一跳跃 | 假想例子无测量结论；性能教材专题待补 |
| 功能必要仍须考虑代价 | 工程推理 | 无通用阈值，不要求证明所有方案不存在 |
| Precision/Recall 公式 | 独立指标核查 | 明确一对一匹配和真值完整假设 |
| 错误评论占比等于 FPR | 应否定 | TN 单位须先定义；不能互换 |
| 误报影响使用与信任 | B06 支持工程观察 | 无本项目量化效果，无通用误报阈值 |
| 采纳代表技术正确 | 应否定，B06 提供两者分离实例 | 行为反馈与正确性标签分开 |
| 严重程度和置信程度分开 | 本书操作性约定 | 证据强弱不等于已校准概率；专门依据待补 |
| 四部分风险评论 | 自编模板 | 不说来自 B03，不声称实验优于其他模板 |
| diff 不是完整上下文 | B02 Context 支持 | 调用方例子是推演，不是实测缺陷 |
| 新功能测试和测试质量要核查 | B02 Tests 支持 | 不能从通过状态反推测试有效 |
| 测试通过覆盖全部配置时序 | 应否定 | 针对实际覆盖检查；并发分析仍需专题材料 |
| 按 diff 类型选择重点 | 教学建议 | 没有路由准确率或遗漏率证据 |
| 平均耗时代表全部性能 | 应否定 | 基准设计和统计专题待补，不给性能结论 |
| 公共库与调用方一起评价 | 研究问题与分析视角 | 不声称统一质量函数已成立 |
| Rust 泛型抽象一定值得 | 未成立 | 必须后续性能、维护与配置验证 |
| 定位→生成→验证→排序 | 本研究拆解方式 | 不是整个领域唯一技术谱系 |
| 已接受 PR 即优质金标签 | 未成立 | 沿用既有标签偏差与最近邻笔记，不开始采集 |

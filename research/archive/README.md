# 公开归档与复现材料

GitHub主仓库保存研究正文、脚本、协议、经过筛选的实验输入输出及失败记录，不充当构建缓存或未经许可的第三方镜像。

|位置|内容|用途|
|---|---|---|
|`chapters/research-topics/`|按研究问题组织的综合结论|论文、阶段汇报和book的主题入口|
|`research/notes/`|论文分析、实验解释、局限和负结果|从主张追溯到证据|
|`research/protocols/`|任务、配置、标签规则、选择方案|区分预定协议与事后分析|
|`research/evidence/runs/<批次>/`|输入摘要、命令、原始结果、失败日志、派生分析|复核和复跑；保留旧批次|
|`research/archive/sources.json`|外部仓库版本、获取入口、许可与归档边界|不把公共可访问误认为任意再分发许可|
|`research/archive/licenses/`|本次补存的来源许可原文及来源元数据|与源码摘录保持关联，不替代逐文件许可审计|
|`research/archive/snapshots/`|公开文件清单、字节数与SHA-256|核对交付内容，不是法律公证或可信时间戳|

## 不直接上传的内容

- `.build/`、`.tools/`和`dist/`：编译缓存、外部工具、重复数据与生成网页；用固定版本、校验值和获取/构建脚本恢复。当前并非所有工具都已实现干净机器一键恢复，不能宣称完整离线复现包。
- `research/evidence/originals/`：保持本地论文/网页原件库的既有忽略策略。公开来源台账保留URL、获取时间、摘要和阅读范围。既往已提交PDF仍在历史中，本轮不重写历史或声称完成它们的再分发审计。
- 未核实再分发条件的完整外部仓库/数据集：只登记版本、下载入口、已有文件级清单和许可缺口，不直接镜像。
- 凭据、私有数据、待保密专利交底：不纳入公开材料；需要时另建受控存储，而非隐藏在公开仓库的子目录。

## 发布规则

本仓库当前公开。普通研究记录与待保密技术交底必须分开处理；不得将Git提交日期当成专利权属或新颖性的证明。需要披露决策的专利内容应另行审核，本归档流程不作法律判断。

先运行内容/链接检查、相关实验校验、文件体量及凭据模式检查，再创建归档清单和提交。大于50MiB的单文件默认阻止进入这套普通Git归档流程，先评估许可和适合的存储渠道；当前未配置Git LFS或Release大对象仓库。

不挪动既有run目录，以免破坏已引用的路径与摘要。失败实验和不利结果与成功结果同等留存。对第三方源码保留已有头部；研究生成的改写和测试替身通过运行说明标明，不能冒充原版。

## 检查入口

```sh
python3 scripts/archive_research_snapshot.py --output research/archive/snapshots/新快照.json
python3 scripts/archive_research_snapshot.py --verify research/archive/snapshots/新快照.json
```

凭据检查是高置信模式筛查，不保证发现所有敏感信息。快照只覆盖清单中的公开文件，不把未上传的缓存也算作已备份。Git提交号和实际push结果另行报告。

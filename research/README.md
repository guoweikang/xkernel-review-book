## 研究目标与边界

用户提出：为 X-Kernel 的 crate、mod、结构体建立职责语义元数据索引，结合代码重复
检测，检查已合入的存量仓库，也支持 PR diff 增量分析。研究既包括直接复用已有能力，
也包括从多份实现中提取公共模块、以 Rust 类型/泛型等保留定制部分，并给出合理优化建议。
AI review 是应用入口之一，不是系统的范围边界；公共抽象不要求仓库里已有可复用模块。
研究还需形成可追溯的论文和专利素材。已有基线工具执行、Rust适配及局部机制实验，尚未证明整体方法的独立评测收益。
后续真实评测覆盖 X-Kernel、ArceOS、Starry、星绽等候选 Rust OS；受控构造与真实工程
实验分开设计。当前仍以xkernel为主试点，保留原六阶段，不将局部执行视为整阶段验收。

语义索引、克隆检测、契约可行性、评价系统是同一研究主线。xerj 等工具只作为
实现候选和对照对象；其评估不替代主线，也不代表已经选型。

## 恢复工作时的阅读顺序

学习入口：[AI Review 知识图谱 v0.1](KNOWLEDGE-MAP.md)，汇总共同讨论、关键关系与待补知识。

1. 阅读[阶段研究报告](notes/2026-11-18-stage-progress.md)：整体位置、哪些实验已做、哪些主张仍未成立；前期基线综合保留在[11月16日报告](notes/2026-11-16-stage-research-review.md)。
2. 从[研究目标专题](../chapters/research-topics/scope.md)进入输入、发现、职责、确认、评价和优化各专题；主题综合优先于日期流水账。
3. 阅读 [PROGRESS.md](PROGRESS.md) 顶部：最近批次、未决问题和下一步；六阶段规划见 [RESEARCH-PLAN.md](RESEARCH-PLAN.md)。
4. 由专题链接进入 `notes/` 的协议与分析，再进入 `evidence/runs/` 查看原始结果和检查。
5. 从 [SOURCES.md](SOURCES.md)、[证据状态](notes/2026-11-11-research-evidence-status.md)核对论文阅读和工具执行层级；历史材料中的下一步按其日期理解。

## 每次子任务如何归档

- 开始前在 PROGRESS 中明确它服务哪个未决问题；没有改变研究目标的小任务继续归入本目录。
- 新来源登记稳定编号、URL、版本/公开日期、阅读深度和局限。检索线索与已经核对的证据分开。
- 调研写入日期化专题笔记，引用来源台账和证据；不要把临时结论散放到通用 reports。
- 完成后更新 PROGRESS 的工作日志、结论状态及下一步。用户未确认的建议仍标为提案。
- 实验归档到 `evidence/runs/<日期-主题>/`，保存输入身份、配置、命令、原始结果和检查；解释和协议登记到主题目录。
  区分开发控制、独立评测、原工具运行和完整论文复现，保留失败与负结果。
- 事实、推断、用户决定、研究假设分别标明；新结论更正旧笔记时留下日期和理由。
- 不把研究笔记自动混入 CG 规则 PR。本次整理未提交/推送；历史提交和当前本地增量分开报告，不将忽略目录的大工件称为已上传。

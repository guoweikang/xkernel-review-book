## 图谱总览

```text
AI Review：根据需求与上下文，形成有证据的审查意见
│
├─ 评价对象 [已讨论]
│  ├─ 代码／改动质量：正确性、性能、内存、安全、可维护性
│  ├─ 单条意见质量：是否成立、证据是否充分、是否可行动
│  └─ 整个 reviewer：精确率、召回率、严重问题覆盖、复核成本
│
├─ 判断依据 [已讨论]
│  ├─ diff → 识别变更性质与风险，而非限制审查范围
│  ├─ 需求与规则 → 确定评价标准
│  ├─ 调用方／依赖／配置／接口契约 → 确定影响条件
│  └─ 历史评审／测试／性能测量 → 提供不同强度的证据
│
├─ 判断链 [已讨论]
│  └─ 事实成立？ → 后果是什么？ → 需求下是否值得接受？
│     ├─ 性能代价 ≠ 性能缺陷
│     ├─ 必要功能 ≠ 任意代价都可接受
│     └─ 合理方案比较 ≠ 证明不存在其他实现
│
├─ 方法分工 [已讨论]
│  ├─ fmt／clippy／静态规则 → 可机械化的检查
│  ├─ 检索与 metadata → 找到相关代码及证据入口
│  ├─ AI → 理解上下文、提出假设、组织证据
│  └─ 测试／分析工具／人工 → 核验结论
│     └─ 能否主动运行工具 → 权限与工作流问题
│
├─ 意见表达 [已讨论]
│  ├─ 严重程度：若成立，后果多坏
│  ├─ 置信程度：目前证据多强
│  └─ 潜在后果 + 具体证据 + 缺失条件 + 验证办法
│
├─ 评价体系 [已讨论，部分待补]
│  ├─ 精确率：提出的问题中，真实问题的比例
│  ├─ 召回率：真实问题中，被发现的比例
│  ├─ 误报 → 复核成本／信任损耗；漏报 → 问题遗留
│  ├─ 未知真实问题总数 → 无法直接从日常评论算召回率
│  └─ 标注协议／独立测试集／校准／统计不确定性 [待学习]
│
└─ 项目专题：重复功能与公共抽象 [已讨论]
   ├─ 相似 ≠ 功能重复 ≠ 可合并 ≠ 值得合并
   ├─ 复用现有实现／调整抽象／新抽公共机制／保持独立
   ├─ 定位 → 生成 → 验证 → 排序：分别检查失败原因
   ├─ 评价公共模块 + 调用方整体，不只是代码减少
   └─ 全仓扫描 + diff 增量检查；跨组累积不等于版本增量
```

## 关键关系与边界

| 起点 | 关系 | 终点或限定 |
| --- | --- | --- |
| 修改类型 | 决定重点 | 文档、API、热路径、数据结构、锁序等采用相应审查重点 |
| diff | 触发检索 | 未修改的调用方也可能受影响 |
| 测试通过 | 提供有限证据 | 不保证新功能覆盖、测试正确或全部配置/时序安全 |
| 合入记录 | 提供接受信号 | 不保证所有质量维度改善 |
| 性能担忧 | 需要验证 | 机制分析不替代相关负载下的测量 |
| 严重程度 | 影响核查优先级 | 不自动提高置信程度 |
| 多模型共识 | 可帮助筛选 | 不等于独立人类认可或真值证明 |
| 评分改善 | 表示目标指标改善 | 不自动证明工程质量整体提升 |
| 评论被采用 | 是反馈信号 | 不等同意见正确，更不直接给出召回率 |
| 概率生成 | 不妨碍外部核验 | 自信语气也不构成证据 |

## 精确率、召回率与误报率

教学例：已知 10 个真实问题，提出 8 条意见，其中 6 条分别对应真实问题，2 条不成立。
精确率为 6/8，召回率为 6/10。2/8 是所提意见中的错误占比（本例为 1−精确率），
不是通常定义的假阳性率 FPR。FPR = FP/(FP+TN)，需要先定义负例及判定单位。
真实 review 还需定义一条意见与一个问题的对应关系，处理重复评论和严重程度。

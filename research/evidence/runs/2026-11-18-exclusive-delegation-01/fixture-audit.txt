Oracle-by-oracle findings
1. positive_rejects_before_callback: real positive directory constructed with parent; seed insertion requires no prior winner and verifies inode attachment. Requires exact AlreadyExists, zero callback invocations and original cached pointer. It would not accept an error from callback, since callback returns Ok and count must remain zero. Covers inode-attached positive rejection, not every positive node subtype.
2. callback_error_unchanged: seeded negative is strongly retained by test. Requires exact NotFound, callback exactly once on that identity, negative type and no inode, unchanged cached identity. NotFound can also arise from unrelated lookup paths in general, but invocation count and pointer assertions rule out a mere pre-callback NotFound being counted as success. Callback deliberately makes no inode/cache mutation, so unchanged state is valid for this case, NOT a rollback contract for arbitrary callbacks.
3. ok_without_instantiation: requires InvalidInput after exactly one callback on the seeded pointer, with negative/no-inode state and cached identity unchanged. Explicitly distinguishes callback Ok from method success. Does not inject malformed divergence of type flags/inode.
4. success_preserves_identity: callback moves prepared regular-file inode into actual private instantiate. Requires callback once, exact callback and returned Dentry pointer, inode-attached/nonnegative state and cache identity. Failed instantiate cannot masquerade as success because result must be Ok. It does not independently assert exact attached inode pointer; it checks the protocol's child identity and instantiation state, not a stronger inode-equivalence oracle.
5. nonexclusive_existing: invokes unchanged general method with false; exact Existing variant/original pointer and zero callback required. Rejects Created and any Err. This is a regression check of existing general behavior, not an independent expected-answer implementation for exclusive wrapper.
6. nonexclusive_created: same general false mode on negative input; requires exact Created variant/pointer, one callback on seed, attached/nonnegative state and cached identity. Distinguishes both enum branches without trusting proposed adapter output to compute expectations.
These map directly to the protocol observations. All expected answers are explicit errors/counts/identities/states/variants rather than outputs generated by proposed delegation. Setup, access, guard and cleanup assessment
Existing registered child module has descendant private access to instantiate and LookupCreateResult. make_dir_entry_with_parent constructs a real directory inode; instantiate locks attached inode, adds alias, updates flags and stores inode. Callbacks use that operation, not recursive parent namespace creation, so no fixture-introduced recursive parent lock acquisition is apparent in inspected code.
lookup_locked first returns live lookup_cache_entry on these seeds. Strong child locals keep weak slots alive; tests install no PAR flag, so the filtering lookup path does not hide their entries. Unlike earlier PAR mutation fixture, using lookup_cache for post-call observations here is appropriate for explicitly non-PAR live states. It remains a filtered observer, not proof of arbitrary raw-map contents or absence of unrelated slots.
Parents are fresh and unbound to superblocks. Children own parents while parents index weak children, so these fixture links do not introduce an owning parent-child cycle. No explicit uncache is needed to release a superblock retention owner, because none is introduced. No PAR flag/manual guard/waiter needs cleanup. Counters and identity booleans are local mutable captures; prepared inode moves make successful callbacks valid FnOnce use. Distinct tests use independent objects even if kernel harness schedules them concurrently. Each individual fixture interaction is sequential.

Limits / handoff
These six tests do not dynamically observe parent namespace guard lifetime, callback capture destructors, final-owner drop order, panic/unwind, allocator/clone budget or concurrency. Positive/error callbacks mostly borrow local counters; success owns an inode but adds no Drop trace. Static admission remains necessary for those boundaries and does not become proved by fixture pass.
Missing cases include pre-lock invalid parent/name errors, uncached backend lookup, callback state mutation followed by error, malformed flag/inode combinations and racing aliases. They are scope limitations, not justification to add tests or change the frozen oracle mid-run. No extra case is requested.

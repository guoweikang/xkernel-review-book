case-001 — already_shared
The file and symlink constructors already delegate to the same mechanism:
fs/kvfs/src/node/inode.rs:1513-1520 and :1536-1543 call
new_file_with_address_space_operations, defined at :1656-1674. That helper
assembles InodeParts and delegates through from_parts (:1676-1680) to shared
allocation/address-space construction (:1701-1728).
Residual Arc trait-object conversions are adapters, not independent inode
construction mechanisms. Preserve the file's FileOperations bound and Some
operation table (:1508-1516), versus the symlink's weaker bound, symlink-mode
assertion, and None table (:1531-1539). None becomes no_open_file_operations
at :1719. Both preserve supplied flags, address-space operations and init;
neither exposes a fallible result. Do not impose FileOperations on symlink
implementations merely to merge the wrappers. No confirmation candidate.

case-002 — confirmation_candidate (partial overlap only)
Independent common mechanism exists at fs/kvfs/src/node/dentry.rs:832-840
and :935-943: lock the parent's children map, upgrade an existing weak entry,
return a live winner, otherwise replace/insert a weak reference, then unlock.
Both subsequently retain the inserted entry through SuperBlock::cache_dentry
(:841-843 / :944-946). Shared use of Arc/map primitives and cache_dentry is
already delegation at a lower level; the conditional map transaction itself
is independently implemented twice.

Smallest proposed boundary: only that locked live-winner-or-weak-insert
transaction, returning Option<Dentry> and releasing the children lock before
return. Keep eligibility checks and superblock retention in the wrappers.
The boundary must accept the existing owned String without copying it, while
materializing the borrowed lookup name only on insertion, as today; an owned/
borrowed name carrier is sufficient conceptually. It must borrow the candidate
without adding a strong clone. This is a proposed boundary, not implemented code.

Necessary differences: insert_cache consumes String and Dentry and gates on
can_cache_children AND can_cache_as_child (:933-934; definitions :799-806).
The latter honors PERSISTENT despite DONTCACHE. cache_lookup_candidate borrows
both inputs and intentionally bypasses those gates: lookup_locked installs a
PAR_LOOKUP negative candidate while holding its lookup mutex (:1079-1088), even
for a non-cacheable parent. Final admission/retraction belongs to lookup_locked
(:1091-1134). Its error propagation and filesystem lookup callback must stay
outside this boundary. Ordinary lookup_cache_entry filters PAR_LOOKUP (:820-828);
the proposed insertion transaction must NOT use that filtered result to decide
absence. Preserve consumed-versus-cloned dentry retention in the wrappers and
the unlock-before-superblock-cache ordering. cache_dentry itself takes another
cache lock and drops any replaced owner afterwards (fs/kvfs/src/super_block.rs:
1178-1183), so widening the children-lock lifetime is not neutral.

ONE adoption-changing obligation: demonstrate that both wrappers retain the
same atomic live-winner/expired-slot replacement behavior, including a live
PAR_LOOKUP winner, without moving superblock retention under the children lock.
A failure of that transaction-equivalence obligation rejects adoption.
Exact existing verification entry: no suitable entry establishing that full
obligation was identified in the permitted inspection. Directly registered test
module is fs/kvfs/src/node/dentry.rs:1657 -> fs/kvfs/ut-tests/node_dentry.rs.
Nearby existing entry test_parallel_lookup_candidate_does_not_escape_cache_snapshot
at fs/kvfs/ut-tests/node_dentry.rs:1147-1160 checks snapshot filtering, but does
not exercise a competing live winner, expired-slot replacement, or lock ordering.
Other inspected tests (:1127-1144, :1163-1193, :1196-1213) cover non-cacheable
retraction and candidate completion, not that complete obligation. This is a
conditional confirmation candidate, not a validated refactoring recommendation.

case-003 — already_shared

policy, callback timing, error mapping, or lifecycle-lock expansion is warranted
to remove these necessary wrapper differences. No confirmation candidate.

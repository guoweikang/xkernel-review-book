没有真实代码、Rust 可执行验证、性能测量、架构最优或拆分收益声明。
没有运行被测模型、派发评审代理、调用推理 API、生成预测或伪造效果结果。

这些“显式给定事实 + 简单规则”可能只是规则应用控制，不支持文档理解、工程定位、行为抽取或职责检测效能的结论。

二、文件结构与分层
cases.json.input_contract：共同任务、声明类型、四标签释义、分轴输出及派生显示定义。
cases.json.cases：八个中性 case ID、机制族 ID、input。
每个 input 有 subject、question、evidence；各例自包含，不需要其他例的事实。
每例七项声明：
  R1：机制实现归属与通常禁止范围。
  R2：另一方的策略职责，以及调用/委托不等于自行实现的规则。
  F1：被指定机制方已有且可用的实现。
  F2：另一方明确允许的策略行为。
  F3：实际由另一方委托还是自行实现机制。
  E1：覆盖 F3 的显式迁移许可，唯一适用条件引用 C1。
  C1：行为发生时迁移窗口开放状态，value 为 true / false / unknown。
R/F/E/C 的来源全部是研究者题内规定，不冒充维护者确认或独立工程证据。
证据 ID 在单个案例内解析；跨例应使用 case_id#evidence_id。不存在一个全局 R1 可被任意跨例引用的约定。

cases.json.evaluation_answers 是完全独立的评价字段：
  每例包含 case_id、reference、派生 label、rationale、required_evidence_ids、
  conditional_branches、missing_evidence_ids。
unknown 的缺失证据 ID 指向“已明确记录状态未知”的 C1，并非悬空引用或暗示条件已证实。
required_evidence_ids 是判定应使用的题内声明，不是对现实事实的真实性证明，也不声明最小充分证据集。

三、采纳用户转述的 Goodall 分轴建议
reference.base_rule = allowed | forbidden | unknown
reference.exception = applies | not_applicable | unknown | no_clause
reference.real_project_violation = not_evaluated

通常规则与例外分开评估：迁移许可不会把通常规则 forbidden 改写为 allowed。
四标签 conforming / divergent / exception / unknown 仅作 reference 的派生显示，不能替代三轴或代表真实项目违规。
在本批的状态域内：
  allowed -> conforming；
  forbidden + applies -> exception；
  forbidden + not_applicable/no_clause -> divergent；
  base_rule unknown 或 forbidden + exception unknown -> unknown。
本批每例都有 E1，因此不出现 no_clause；通常规则和行为均给定，因此没有 base_rule=unknown 的实例。
不为覆盖全部枚举而扩充超过八例。两个 unknown 测的是 exception=unknown，不是职责规则缺失。
unknown 的两条分支也有完整三轴 reference，real_project_violation 始终 not_evaluated。
Goodall 建议来自用户转述，未声称已独立读到审议原件，也未把建议采纳当成输入准入通过。

family-01 是“资源描述解释 vs 驱动策略”：
R1 指定 U17 实现字段宽度、字节序、缺省值及区间边界解释；
R2 指定 U28 按设备模式选择启用区间，允许调用 U17。
family-02 是“缓冲区管理 vs 调用方策略”：
R1 指定 U43 实现空闲表、分配归还、占用计数及相应不变量维护；
R2 指定 U56 选择批量上限及等待/拒绝策略，允许调用 U43。
名称 U17/U28/U43/U56 是无语义标识，不用模块名字判断答案。
规范按实际“实现判断/维护状态”区分职责，与“调用接口/传参/使用返回值”分开；
仍调用指定实现方也不能豁免本地另行实现，但本批不新增混合调用案例。
本题不评价缓冲区算法安全性、资源解释正确性或指定归属本身是否合理。

五、最小干预
各族 R1/R2/F1/F2/E1 的完整声明在四例中完全相同。
明确符合 -> 明确越界：只变 F3，委托改为自行实现；C1 保持 false。
明确越界 -> 显式例外：仅变 C1.value，false 改 true。
明确越界 -> 条件未知：仅变 C1.value，false 改 unknown。
除 case ID 外，同族 subject/question 不变；家族 ID 固定。
E1 的存在不等于例外适用，窗口关闭不等于没有条款。
unknown 保留同样的确定行为，不以行为提取不全人为制造未知：
  C1=true -> exception（通常规则仍 forbidden）；
  C1=false -> divergent；
  当前 C1=unknown -> unknown。
本设计有意不增加额外日期计算、范围匹配、规则冲突、性能条件或模型失败诱因。

4. embedding、distance、score 的准确含义
P/repository/embedding_provider.py:39-49：provider 返回单位向量；L2 距离转 cosine 的前提是单位范数。
P/repository/sqlite_vec_index.py:416-441：向量近邻按 distance 升序；similarity = max(0,min(1,1-distance^2/2))。
P/repository/pgvector_index.py:488、:521-540：使用 cosine distance 运算符 <=>，similarity=1-distance，裁剪到 [0,1]。
P/repository/search_reader.py:1155-1157：embed_query(query_text)。
P/repository/search_reader.py:1320-1351：同一 (type,row id) 多个命中 chunk 取最大 similarity，再用 min_similarity 过滤；不是平均全文相似，也没有按重复 chunk 数除以总 chunk 数。
因此即便向量 score=0.8，也不能读作“80% 内容重复”或“80% 概率为重复笔记”。它是特定模型、预处理与匹配 chunk 下的排序信号。

5. score fusion：仅混合检索，不能套到 write 的 VECTOR 建议上
P/repository/search_reader.py:77-79、:305-349：FTS 按 abs(raw_score)/当次候选最大绝对值归一化；SQLite 原始 BM25 为负，Postgres ts_rank 为正。vector score 不再按当前最高向量分数归一化。
融合公式 = max(v,f) + 0.3*min(v,f)；双路范围 [0,1.3]，单路 [0,1]。按 (type,id) 合并检索结果，不是合并原笔记，也不是 RRF。
例如 v=0.8、归一化 f=0.6，融合值 0.98；v=f=1 得 1.3。这里的 0.98 或 1.3 均为排名分数，不是 98% / 130% 重复。
write 建议显式 VECTOR（P/mcp/similar_notes.py:105），不会用这套 FTS+vector 融合。
但 VECTOR 不等于永远只按原始 cosine 排序：P/repository/search_reader.py:1076-1113 表明若配置 reranker，向量检索也可重排。
P/repository/search_reader.py:389-391、:761-784：重排调用 provider.rerank，候选前缀的 score 被重排相关性分数替换，尾部另降分；不能把所有搜索输出 score 都称为原始 cosine。

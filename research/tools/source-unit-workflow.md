# 源码单位提取：固定执行与验收流程

## 1. 用途与边界

此流程生成固定 Git 提交下、指定物理 package 范围内的源码单位清单。
它验收的是**提取流程及证据一致性**，不是重复功能检测、代码质量或重构收益。
执行者无需临时决定扫描范围、工具版本、验收数量或失败处理方式。

当前默认协议：`research/protocols/source-units-v2.json`；v1 文件和运行产物保持不变，仍可显式指定复跑。
入口：`scripts/run_source_workflow.py`。
当前协议固定 X-Kernel `7e3ac94431a0dbb376d2fc8d85098deeff1bba09`，
范围为 kvfs、kspin、klazy、macros，Rust 工具链 1.95.0，依赖由 Cargo.lock 固定。
它是已有样本的回归协议，不是对未来任意仓库都适用的质量阈值。

## 2. 一条命令执行

前提：Python 3.11+、Git、已安装的 Rust 1.95.0（含 rustfmt）、相应 Cargo 依赖缓存，
以及包含指定提交对象的本地 X-Kernel 仓库。无需旧工作树 checkout、原始 CI 压缩制品、模型或网络访问。
历史五文件定位对照 JSON 已作为输入保留在 book 仓库，其 SHA-256 由协议固定。

在 book 仓库根目录运行；输出路径必须尚不存在：

```sh
python3 scripts/run_source_workflow.py \
  --repo /root/codes/x-kernel \
  --config research/protocols/source-units-v2.json \
  --output research/evidence/runs/my-source-units-run
```

`--repo` 仅指定本地源仓库，运行时按固定 Git 对象读取，不切换/修改内核工作树。
构建的是 book 内独立解析器，不是内核。Cargo 使用 `--offline --locked`；缺组件或缓存时报告失败，
不由流程自动下载、安装或改用其他版本。依赖自己的 Cargo 构建脚本仍可能运行。
每个文件的解析子进程有 30 秒超时，构建和回归步骤有超时；文件数扩大时总耗时仍会增长。

## 3. 固定执行顺序

1. 创建全新运行目录；已有目录直接拒绝，保护先前证据。
2. 保存协议快照，校验完整提交号、包路径、历史输入哈希及提交一致性。
3. 校验源码对象存在，记录 Rust/Cargo/Python 版本和关键脚本、解析器源码、锁文件、输入文件哈希。
4. 执行门禁自身回归：正常对照加 8 项负向检查。
5. 离线锁定构建、格式检查、15 个构造输入及固定五文件解析回归。
6. 盘点四个 package，保留全部文件分母、属性、单位、解析失败和已知限制。
7. 执行下列门禁，检查运行期间输入文件未变化，保存报告和产物哈希。

v2 在构建后增加18个模块路径案例和3个模块门禁负向检查；盘点后生成模块文件候选。
规则及适用边界见 [模块映射实现记录](../notes/2026-11-05-module-mapping-workflow.md)。

## 4. 自动验收规则

| 门禁 | 固定规则 | 失败处理 |
| --- | --- | --- |
| 输入身份 | 完整提交号；历史输入 SHA-256；回归与盘点提交一致 | 停止或门禁失败，禁止混用 |
| 工具身份 | 回归和盘点使用同一二进制哈希；关键输入运行前后哈希一致 | 门禁失败 |
| 范围 | package 集合与协议一致；文件数量与分母一致 | 门禁失败 |
| 回归集 | 15 个构造输入满足脚本中明确的接受/拒绝/暂不支持期望；五文件与历史对照一致 | 停止，不进入盘点 |
| 失败清单 | v1允许失败文件最多0个；任何非 parsed_by_syn 状态都算失败 | 保留失败文件及原因，禁止从分母删除 |
| 身份冲突 | 快照 ID 不重复 | 门禁失败 |
| 固定快照数量 | 88文件、2180有body、45无body声明、57外置模块声明 | 报告提取漂移，不自动更新期望值 |
| v2模块映射 | 所有外置声明各有一条记录；50个matched_candidate、7个deferred；目标有受控文件证据 | 门禁失败，不隐藏未知项 |
| v2推断边界 | cfg必须保持not_evaluated，编译归属必须保持not_established | 拒绝无证据升级结论 |

数量期望来自已经核查的固定快照，是**变化报警器**，不是功能正确性的独立真值。
解析器和校验器共享实现仍可能存在共同盲点，名称/数量一致也不证明边界或语义全部正确。

## 5. 输出及退出码

| 退出码 | report.status | 含义 |
| --- | --- | --- |
| 0 | passed_with_limits | 本协议门禁通过，已知限制仍存在 |
| 1 | gate_failed | 完成盘点，但至少一项门禁失败；保留中间产物 |
| 2 | execution_failed | 前置条件、命令或协议处理失败；目录已创建时尽可能写报告 |

命令行参数错误或输出目录已存在也返回2，但不会覆盖旧目录写新报告。
磁盘不可写、进程被强制终止等情况下不保证能够写完报告；没有完整报告不能视为成功。

每次运行目录包含：

- `protocol.json`：本次协议快照；
- `regression.json`：构造样例与固定文件回归结果；
- `inventory.json`：源码单位及失败清单；
- `modules.json`：v2模块候选、歧义/暂缓原因及文件角色假设；
- 各步骤 `.log`：执行命令对应输出；
- `report.json`：状态、逐项门禁、时间、输入哈希、产物哈希、已知限制。

源代码来自固定 Git 树；宿主完整环境、系统依赖和 Cargo 缓存并未容器化或供应链认证。
这些记录便于复查，不保证跨机器二进制哈希相同。

复查已保存结果，不重建内核或解析器：

```sh
python3 scripts/check_source_workflow.py --run research/evidence/runs/my-source-units-run
```

该命令核对产物哈希并重新计算门禁。它不能防止有人同时伪造产物和报告，
因此不是签名、可信时间戳或证据真实性认证。当前门禁检查器也应与当时记录版本对应。

## 6. 工具自身的固定验证

```sh
python3 scripts/check_source_workflow.py
python3 scripts/check_workflow_integration.py \
  --repo /root/codes/x-kernel \
  --run research/evidence/runs/2026-11-05-source-units-v2-verified
```

第一条测试混用提交/二进制、隐藏失败、遗漏失败台账、错误分母、ID冲突、提取数量漂移和缺少样例。
第二条实际验证数量漂移退出1、仓库缺失退出2、已有运行不可覆盖、产物字节改变被拒绝。
负向运行使用临时目录，不改变正式运行结果。第二条会重跑离线解析流程，并非纯静态检查。

## 7. 哪些决策仍需研究者负责

| 决策 | 当前处理 |
| --- | --- |
| 为什么选这些 crate、哪些配置 | 在协议对应研究记录中解释；机器只执行固定范围，不证明抽样代表性 |
| 发现数量变化是否合理 | 先保存失败，再检查新增语法/提取遗漏；不能为了通过而覆盖期望值 |
| 修改协议或解析器 | 新协议版本/独立运行目录，保留旧记录，说明变更原因；禁止静默改写历史结果 |
| 哪些功能重复、是否值得抽象 | 尚未实现；未来需要独立标签、证据与评价协议，不能用本流程通过替代 |
| 外置模块、宏、cfg等未完成能力 | 在协议和结果中明示，不由 Agent 猜测补成确定结论 |

协议变更仍需版本管理和评审；当前工具记录哈希但不会阻止有权限的人修改协议。
这套流程减少临时主观决定，不掩盖研究问题本身仍需要判断。

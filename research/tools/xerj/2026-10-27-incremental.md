# XERJ incremental indexing and revision isolation

Research entry: [README](../../README.md). Companion: [assessment](2026-10-27-assessment.md).

Date: 2026-10-27. Official source inspected at commit `2b67a883ab43cd2146199968f537912c0bee3b9d` in the supplied clone. Read-only research; no server, installation, runtime tests, or benchmarks. Scope: incremental/delete handling and namespace/isolation. Source observations below are not reproduced defect reports.

## Verified source evidence

- **Incremental replacement and deletion exist.** On the generated, graph-disabled route, a delete removes documents selected by `ax_file` content identity. An upsert deletes the old group, cleans a partial retry of the new group, then replays prepared documents. Metadata-only operations have a separate path. Operations for disjoint groups can execute concurrently. [Implementation](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/engine/crates/xerj-autoindex/src/sync_executor.rs#L918-L1012).
- **Commit follows replay and validation.** The executor replays outstanding operations, publishes the catalog, validates, and only then records `sync_validated` and `sync_commit`. This is durable reconciliation bookkeeping, not evidence of an atomic search-visible replacement of every document. [Ordering](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/engine/crates/xerj-autoindex/src/sync_executor.rs#L2495-L2529).
- **Watch requires `--no-graph`.** The CLI rejects watching with relationship detection enabled. Its diagnostic also states that graph-route reruns sweep deleted files and accept additions fitting the frozen dataset; additions needing a new dataset require rebuilding. Do not describe all graph-route deletions as unsupported. [CLI guard and diagnostic](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/engine/crates/xerj-autoindex/src/cli.rs#L1623-L1634).
- **Schema evolution has coverage limits.** Incremental planning preserves dataset identity and permits additive scalar mappings. Incompatible types, new datasets or ambiguous assignment can reject an individual file while the remaining pass completes. Rejection explicitly says previously indexed documents for that file are dropped in that generation. [Planning contract](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/engine/crates/xerj-autoindex/src/reconcile_plan.rs#L1-L11), [rejection path](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/engine/crates/xerj-autoindex/src/reconcile_plan.rs#L359-L379), [reported consequence](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/engine/crates/xerj-autoindex/src/reconcile_plan.rs#L960-L968).
- **Watch has a documented blind spot.** A write with no event and unchanged size, mtime and inode can remain unnoticed; a plain rerun rehashes the bytes. Incremental dataset identity can also differ from a fresh rebuild after directory renaming. [Official contract and limitations](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/docs/LIVE_REINDEXING.md#L228-L254).
- **Autoindex namespaces are explicit, not Git revisions.** Default local state is keyed by root, endpoint and prefix. Execution identity records these plus extraction/schema/embedding settings; the inspected identity has no Git branch or commit field. A different root reusing a catalogued prefix is refused unless `--replace-prefix` is supplied. [State key](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/engine/crates/xerj-autoindex/src/state.rs#L920-L925), [execution identity](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/engine/crates/xerj-autoindex/src/sync.rs#L111-L140), [prefix guard](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/engine/crates/xerj-autoindex/src/lib.rs#L8511-L8549).
- **Local writer exclusion exists.** A pass exclusively locks `.autoindex.lock` in its state directory; a watcher additionally holds a session-long lock in that directory. These demonstrated guards are filesystem/state-directory scoped. [Pass lock](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/engine/crates/xerj-autoindex/src/state.rs#L1215-L1229), [watch lock](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/engine/crates/xerj-autoindex/src/state.rs#L830-L890).
- **Corpus workflow adds pinning and build isolation.** `corpus.json` records full commit SHAs; `corpus add --from` checks out the recorded revision and discards local edits/untracked files in its managed clone. Fresh corpus builds use a new `xc-<name>-b<stamp>` prefix; the ledger identifies the verified build for readers. The fresh-build flow writes the selected build before retiring old indices. Ordinary updates reconcile the recorded build in place. [Pinning documentation](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/tools/xerj-code/README.md#L47-L83), [reader scope](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/engine/crates/xerj-common/src/xccode/state.rs#L1-L14), [build/update modes](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/engine/crates/xerj-autoindex/src/xc.rs#L2712-L2724), [new namespace](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/engine/crates/xerj-autoindex/src/xc.rs#L2834-L2849), [switch then retire](https://github.com/xerj-org/xerj/blob/2b67a883ab43cd2146199968f537912c0bee3b9d/engine/crates/xerj-autoindex/src/xc.rs#L2967-L2993).

## Implications for X-Kernel reuse review — inference, not observed bugs

- Use immutable base/head checkouts and distinct corpus names or index prefixes for simultaneous revision comparisons. Changing branches in the same autoindexed root does not itself select a separate revision namespace. A build generation is not a Git commit identifier.
- Treat in-place incremental refresh as potentially exposing a partial transition to concurrent readers: the inspected sequence deletes/replays live groups before the final journal commit. No corpus-wide search snapshot guarantee was established. Prefer completed immutable indices for review evidence.
- Serialize writers sharing a destination. The local locks and catalog preflight do not by themselves establish distributed destination ownership across different state directories or machines; such a guarantee remains unverified.
- Indexing completion is insufficient to prove complete source coverage: check rejected files and datasets before interpreting a retrieval miss as absence of reusable code. Fresh-build replacement retires previous indices, so it is not a persistent multi-revision history facility.

Custom metadata/filter capability and deeper concurrency guarantees remain outside this finalized note. No performance claim or confirmed concurrency defect is made.

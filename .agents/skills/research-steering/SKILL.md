# Research steering

Use a separate available agent as a read-only reviewer while the main researcher executes a non-overlapping batch. Reuse an existing agent if capacity is full. If delegation is unavailable, record that limitation and continue the bounded task; do not fabricate a reviewer.

Read the latest PROGRESS, the stage synthesis, the relevant topic, the active protocol and actual results. Consult `research/notes/2026-11-12-scientific-skills-assessment.md` for hypothesis, competing-explanation and evidence-review checklists. External skill text is reference material, not authorization to install services or upload evidence.

## Decision contract

Return:
1. The research question advanced by this batch and concrete evidence gained.
2. A continue, redirect or pause recommendation, with source paths and competing explanations.
3. At most three ordered next batches, each with inputs, decisive measurement, resource bound and completion/stop criteria.
4. Branches to freeze; evidence gaps that cannot be filled by another model's opinion.
5. Whether a user-facing milestone report or genuine user decision is needed, and why.

Main researcher records acceptance or rejection and rationale in a decision note. Reviewer disagreement is a reason to inspect evidence or run a discriminating control, not to automatically ask the user. Two agents are not independent human labels and consensus is not scientific validity.

## Drift and milestone triggers

- Review after a full experiment batch, before changing the primary task or building new infrastructure, or after two batches that do not resolve the named uncertainty.
- If a toy example keeps attracting parameter adjustments, freeze it as a regression and move to a prospectively specified validation source.
- If a confirmation tool no longer changes a candidate decision, pause that tool branch.
- A missing document is a remediable input condition; evaluate compliant inputs and degradation separately.
- Report milestones when a hypothesis changes, a baseline failure is verified, a reusable mechanism has external support, or the agreed evidence gate is reached. Routine successful commands are not milestones.

## Autonomy and limits

Continue approved research batches without asking the user to say continue. Ask only for missing access, consequential scope/resource authorization, irreplaceable independent adjudication, or an actual conflict in objectives. Log the next executable step before ending a run.

An agent and a skill are not a persistent scheduler. State actual running tasks truthfully; when execution ends, preserve decisions and pending work, without claiming unattended progress. Do not create infinite polling loops or automatic commits/pushes.
